# 「我们需要」模式（we-need）

> 一个给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）用的
> **agent preset**：把模型的思维链锚定成**中文 +「我们需要…」**风格。

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

---

## ⚡ 30 秒版

**这是什么**：一个「风格」功能，**不是**「性能」功能。

| 你会得到 | 你要知道 |
|---|---|
| 中文思维链（对照 0% → 43%） | **能力上没有提升**——两次 A/B 通过率无差异 |
| 「我们需要…」句式 | 思考更短 → **更快、更省**（实测约 1.6×） |
| 长任务风格不崩 | **需要重启 dsh web 才生效** |

**⚠️ 一个必须说明的副作用**（本文档最后有数据）：本模式会**显著减少"先查证"的行为**——
实测"首次写代码前真正查证"的次数从中位 **30 次降到 6 次**。
在需要精确性的任务上，这可能有害。**详见 [§副作用](#-副作用先查证行为显著减少)。**

## 安装

```sh
mkdir -p ~/.dsh/.agent-presets
git clone https://github.com/<你的用户名>/<仓库名>.git /tmp/we-need
cp -R /tmp/we-need/. ~/.dsh/.agent-presets/we-need/
```

> ⚠️ **目录名必须是 `we-need`**（`preset.yml` 里的 `name:` 只是显示名）。
> ⚠️ **注意结尾的 `/.`**——如果副本目录已存在，`cp -R <源> <目标>`（不带 `/.`）
> **不会覆盖已有文件**，还会造出嵌套目录。已装过的话建议用
> `rsync -a --delete <源>/ ~/.dsh/.agent-presets/we-need/`。

然后**完全重启 dsh web**（preset 在启动时扫描），新建空白会话，
在模式选择里选 **「我们需要模式」**。

**不需要**装 npm 包、**不需要**改 dsh 源码。

## 它做什么

把 DeepSeek V4 系列的思维链**锚定成「我们需要…」中文风格**，同时**保留全部工具能力**。

原理是**把「首轮条件」和「干活条件」拆开**：

| 阶段 | 工具面 | 思维链 |
|---|---|---|
| **首轮（锚定）** | 只有 `bash` + `edit` | 走进「我们需要…」轨迹 |
| **之后（晋升）** | 全部工具自动恢复 | 保持已锚定的风格 |

晋升信号 = 会话里出现第一个持久事件（`tool/call` **或** `assistant/message`）。
**不需要重启、不需要手动切换。**

## ⭐ 实测结论（TL;DR）

### 有效的

| 改动 | 效果 |
|---|---|
| **锚定首轮工具面** | 风格锚定成功（对照 0% → 43% 中文） |
| **每步重新锚定**（`re-anchor`） | 压住 step 之间的漂移 |
| **种子植入**（`seed-graft`） | 真实多轮密度 1.52× |
| **压缩后重整**（`compact-reanchor`） | 长会话风格不崩 |

### ⚠️ 被自己推翻的（**这些也留在文档里**）

| 曾经的结论 | 实测推翻后 |
|---|---|
| `temperature: 0.1` 有 1.93× 收益 | **复现失败**；且**长任务上导致退化循环**（3/3 崩溃）→ 已于 2026-09-23 **关闭** |
| 「整段用中文」的提醒有效 | 改成"第一句锚定"后**实测无改善**（p=0.21），已退回 |
| 本模式提升能力 | **两次 A/B 通过率均无差异** |
| 加条款能治退化循环 | **不能**——循环会把条款本身当填充物（实测「（停止空转）」出现 325 次）|

> 本项目的原则：**每次推翻自己都留在文档里**，不删。完整记录见 `README-preset.md`。

### 贯穿全部实验的单一根因：**思考长度**

它同时决定风格漂移、token 成本和速度。
**所有有效的改动都在压它；所有无效的（并行提示、观察层、历史改写）都没碰到它。**

## ⚠️ 副作用：「先查证」行为显著减少

**这是使用者最该知道的一点**，也是它"只提速不提智"的机制。

同一任务（"生成马里奥游戏，越像越好"）下对比**标准模式**与**本模式**：

| 指标 | 标准模式 | 本模式 |
|---|---:|---:|
| 首次写代码前**真正查证**次数（中位） | **30** | **6** |
| `web_search` / `web_fetch` | 1 / 5 | **0 / 0** |
| 思考中"猜疑词"密度（每千字符） | **0.01** | **0.96** |

**典型对比**：

- **标准模式**：前 20 步全在查资料 —— 搜 SMB 物理常数反汇编 → 抓逐帧数据 →
  下载真实关卡数据 → 才开始写。
- **本模式**：探完环境 → 第 **8** 步就开始写代码，**全程一次网都没搜**。

### 怎么解读（**请不要过度解读**）

**可以说**：本模式的"更快更省"（30 分 vs 46 分、127 vs 239 次调用、¥0.55 vs ¥1.14）
**主要来自少做调研**，而不是"想得更高效"。

**不能说**：**"查得少 = 成品更差"**。该任务下两边判卷都是 16/16 关键词、都能运行；
标准模式反而有 1/2 有效样本是白屏 bug（`lv.kinds.charAt is not a function`），本模式 3/3 能跑。

**可能的原因**：马里奥这类任务**不需要精确常数**（差不多就能玩）。
在**必须查准**的任务上（真实 API 对接、特定版本行为、精确规格），"少查"才可能致命。

> 🔬 **这一点未定，欢迎复验。** 判据应是**外部**的（真实调用成功 / 规格测试通过），
> 而不是"看起来像"。若你做了实验，欢迎开 issue 贴数据。

## ⚠️ 已知问题 / 限制

1. **退化循环**（模型陷入无意义重复直至输出预算耗尽）。
   - 触发场景：**开放式、没有明确终点**的任务（如"反复权衡要不要验证"）。
   - 已缓解：关闭 `temperature`（实测 3/3 崩溃 → 3/3 正常）。
   - **未根除**：加条款/改措辞都被证明**无效**（循环会换形态）。
2. **风格会随对话变长衰减**（漂移）。语言在每段思考的**前 40 字符**就锁定，
   火源是"紧跟英文工具输出之后"。**目前没有可靠解法**。
3. **需要重启 dsh web** 才能让 `.mjs` 改动生效（刷新页面无效）。
4. **本 preset 只测过 DeepSeek V4.1-Flash**，其他模型未验证。
