# 马里奥 A/B 实验报告（2026-09-23）

> 任务原话：**「生成马里奥游戏，越像越好，没其他要求」**
> 用户要求：对比 we-need 模式与标准模式的**完成效率、花费**，以及**我们的改进到底有没有生效**。

---

## 0. 一句话结论（先看这个）

| 问题 | 结论 |
|---|---|
| **we-need 在真实使用里安全吗？** | ❌ **不安全**。线上 preset 开着 `temperature: 0.1`，在这个任务上 **3/3 全部退化循环、被 max-tokens 强断、25 分钟内崩掉、产不出可玩游戏** |
| **关掉 temperature 呢？** | ✅ **可靠**。3/3 全部正常完成，都产出能跑的游戏 |
| **省时间省钱吗？** | ✅ 明显。比 base 快 **1.5×**（30 分 vs 46 分）、便宜 **~1.6×**（¥0.55 vs ¥1.14） |
| **游戏质量更好吗？** | ⚠️ **本实验里 we-need 反而更稳**（3/3 能玩 vs base 1/2），但**这不是风格带来的**，且样本太小 |
| **⭐「第一句锚定」改动生效了吗？** | ❌ **没生效**。漂移无显著改善（**p=0.21**），`我们` 甚至更少（1.74 vs 2.73 次/段） |
| **能说"这模式提升能力"吗？** | ❌ **不能**。设计无法支撑因果结论（见 §6） |

**最重要的单个发现**：线上 preset 的 `temperature: 0.1` 在长生成任务上是**致命**的。
这不是风格问题，是**参数问题**——而且它已经在线上开着。

## 3. ⭐ temperature：本实验最硬的发现

线上 preset（`agent.cordis.yml:124-136`）`temperature: 0.1` 是**开着**的。
在长生成任务上，它导致了**退化循环**（§25.4 记录过的同一病症，再次复发）：

| run | 墙钟 | 结束原因 | 思维链段数 | 最长单段 | 其中重复覆盖 |
|---|---:|---|---:|---:|---:|
| weneed/run1 | 267s | `max-tokens` | 9 | **128,199 字符** | 65,152 |
| weneed/run2 | 264s | `max-tokens` | 9 | **161,810 字符** | 20 |
| weneed/run3 | 283s | `max-tokens` | 15 | 137,328 | 0（见下）|

循环的实际内容（run2 原文）：
```
（开始。）好。OK。我写。好，写文件。（开始。）好。OK。写！我现在写。
（开始写。）好。OK。写！我现在写文件。（开始。）好。OK。我写。好，写。
```
——**正是 persona 反空转条款要治的那个病**，但这次参数把它重新点燃了。

**⚠️ 重要区分**：这是**参数**问题，不是风格问题。
温度关掉的臂（其余配置**逐项相同**，唯一差异是 `enabled: false`）**3/3 全部正常完成**。

**行动建议（给用户）**：把线上 preset 的 `temperature` 关掉，或至少别在长任务上开。
一行改动：`agent.cordis.yml` 的 `temperature` 行 `enabled: false`。

## 4. ⭐「第一句锚定」改动：**没测出效果**

第十六棒把 `re-anchor` 的 6 条提醒从"**整段**用中文"改成"**第一句就必须中文**"，
依据是 §25.3 的机制（语言在第一句锁定）。**本次做了严格对照**：
两臂**唯一差异**是 re-anchor 指向新/旧文件。

**干预确实送达了**（不是没生效）：
- 新锚定臂：re-anchor 注入 **125 次，125 次都含「第一句」**
- 旧锚定臂：注入 186 次，含「第一句」**0 次**

**但漂移没有改善**：

| 指标 | 新锚定（n=3） | 旧锚定（n=3） | 检验 |
|---|---:|---:|---|
| 段数 | 235 | 293 | — |
| **开头无中文的段** | 76（**32.3%**）| 80（**27.3%**）| Fisher **p=0.21** |
| 跨段惯性 | 0.64 | 0.67 | — |
| 「我们」**每次/段** | **1.74** | **2.73** | 新锚定**更少** |

**结论**：
1. **无统计显著差异**（p=0.21）——**"改了措辞"这件事没有可测效果**；
2. 方向甚至**相反**（新锚定英文开头比例略高、`我们` 更少）；
3. ⚠️ **诚实标注**：n=3/臂、共 528 段，**功效不足以证明"等价"，只能说"没测出差异"**。

**为什么会失效？** 看那些"开头就英文"的段，全都是
`Let me…` / `We need…` —— **正是 §25.3 说的"火源"**。
说明：**光在提醒里说"第一句要中文"，挡不住模型在读完英文工具输出后直接接英文**。
→ 这**支持** §25.3 的方案 C（检测英文开头 → 下一步强干预），**不支持**继续加措辞。
→ **建议：不要再在提醒语上做加法**（本次证明无效），要么上 C，要么承认这是模型层限制。

## 6. 这个实验**能**和**不能**得出什么

**能**（本 harness、本任务、如实陈述）：
1. 线上 preset 的温度设置在长生成任务上会导致退化循环（3/3，干净臂复现）；
2. 关掉温度后，we-need 比 base 快 1.5×、省 1.6×，且完成率更高（3/3 vs 2/6，且 base 那 2 次里还有 1 次是白屏）；
3. 「第一句锚定」措辞改动**无可测效果**（p=0.21）。

**不能**：
1. ❌ **不能说"这模式提升能力/提升游戏质量"**——we-need 与 base 同时差
   **persona + 8 个插件**（我用 `--dump-config` 逐行 diff 确认过差异清单），
   且 base 有效样本只有 **1** 个。观察到的是"一揽子配置"的差异，**不是风格的因果效应**。
2. ❌ 不能说漂移与质量有关——本次漂移指标和判卷结果**没有建立关联**。
3. ❌ 不能把"更省更快"归因于"中文思考"——省时间很可能主要来自
   **更少的工具调用**（127 vs 239），而那可能是 persona 里
   「不要做无谓的工具调用」「改完验一次就够」那几条**效率条款**的直接结果，
   与"中文"无关。**要分离这两者需要单独消融实验。**

**⚠️ 顺带发现的两个真 bug（与本实验无关，但值得记）**：
- base 臂会**疯狂调 `read_image`**（run2 达 **61 次**），撞上 API 的
  **单会话 60 张图片上限**而死；
- `dsh-subagent` 插件存在崩溃：`hasPending`（`lib/index.js:712`），
  base 两次因此中断。

## 7. 给下一棒的建议（按优先级）

1. **先关线上 temperature**（一行改动，收益明确，见 §3）；
2. **不要再给提醒语加措辞**——本次证明无效；要做就做方案 C（检测+干预）；
3. 若要证明"风格本身有用"，必须做**消融**：把 persona 拆成
   「中文风格」段 与「效率条款」段，分别单独开——这是唯一能分离因果的设计；
4. base 样本要补到 n≥5（它失败率高，需要更多次才能拿到有效样本）；
5. 本目录的坑记录在 **`NOTES-methodology.md`**，**动手前先读**——
   尤其"用同一个正则校验自己"那个循环论证的坑。

## 9. 真实使用复核（2026-09-23，用户报的「又出现无限空转」）

**用户报的会话**：`某次真实会话`（标题「为某个模型开启视觉功能配置」，cwd `<路径>`）。

| 事实 | 值 |
|---|---|
| 用的 preset | **we-need**（11:43:20 运行中切过去的）|
| wire 上的 temperature | **0.1**（`request/header` 实证）|
| 任务 | 给 provider-B 的模型打开 `input: [text, image]`（**很小的改动**）|
| 结果 | 11:44:19 开始 → **step 45 空转 59,214 字符** → 11:48:28 用户手动中止 → 11:49:14 重开一轮 → 11:49:19 `completed` |
| 空转内容 | 「好。」× **5,233**、「执行。」× 2,634、**「（停止空转）」× 325** |

**⚠️ 最扎心的一点**：循环内容里反复出现「（停止空转）」「（立刻调用工具）」——
**反空转条款本身变成了循环的填充物**。§25.4 记的"已修好"（10,849 → 0）不成立，
它只是**换了形态**，没有被根除。

**与历史事故同源**：`某次真实会话`（§22 那次 148,326 字符 / 「好。」10,849 次）
同样是 **temperature 0.1**。两次事故、同一个参数。

**为什么"最后还是完成了"**：改动本身在第 44 步前就做完了，
用户中止后**新一轮（step 1）只用了 5 秒就汇报完毕**。
即：**空转不是在"思考问题"，是在"找不到验证手段后不肯收手"**——
它一直在找 typert RPC 的 HTTP 端点（连撞 3 个 404），该收手时不收手。

### 9.1 ⭐ 这回答了第十五棒的一个未决问题

`we-need-交接文档.md:1889` 当时写：

> 两组都没复现循环（真实 10,849 次），而 **temp=0.1 重复反而更少**。
> → **不能说它是主因**；但循环一旦启动，低温可能让它更粘 —— **这一点未定**。

那个结论**基于单轮小样本**（重复 14/17/13 vs 24/73/103 次，思维 5k~20k 字符）。
本次**长任务 A/B（n=3/臂）+ 两次真实事故**给出不同答案：

| 证据 | 温度开 | 温度关 |
|---|---|---|
| 马里奥长任务（n=3） | **3/3 崩**（128k~162k 字符循环）| **3/3 完成** |
| 真实使用（2 次事故） | 均 temperature 0.1 | — |
| wire 实证 | `temperature: 0.1` 真的发出去了 | **完全不发该字段** |

→ **在长任务上，temperature 0.1 是退化循环的主因之一**（本次证据比第十五棒的单轮实验强得多）。
**该把「未定」改成「已定（长任务上）」。**
